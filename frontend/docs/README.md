# 前端项目 开发文档

## 需求说明

### 功能概述
基于 Vue 3 + TypeScript + Vite + Element Plus 的前端应用，提供开发者、管理员与帮众三套视图，覆盖常驻库、联赛日程、出勤库、排表拖拽、录屏审核、数据分析、系统配置等页面，采用浅色雅金风（宣纸鎏金）风格（详见 ui-style-guide.md）。

### 业务目标
- 按 ui-style-guide.md 落地浅金色主题、组件、布局规范
- JWT 认证链路：登录页 → Pinia 状态 → 路由守卫 → Axios Token 注入
- 角色区分：开发者仅见系统配置与系统日志，管理员完整菜单，帮众仅可见首页（比赛焦点与录屏待办）/录屏上传（联赛总览）/个人战绩/修改游戏 ID/联赛日程（详情内录屏提交与数据分析只读）

### 用户场景
- 开发者：创建帮会、派发账号、删除帮会、系统日志（操作审计）
- 管理员：登录后管理成员、创建赛程、维护出勤、拖拽排表、审核录屏、导入 CSV 分析、调整小队分配、系统配置
- 帮众：首页查看比赛焦点与录屏待办、浏览联赛总览提交录屏链接、查询个人战绩、提交游戏 ID 改名申请、查看联赛日程与赛程详情（只读）

### F04 保存约定

- `lineupBoard` 的自动保存与手动保存共用串行任务；每次发出独立载荷快照，在途期间的新编辑按版本补存，只有最新编辑全部写入后才显示「已保存」。
- Tab 重载先等待保存成功，再读取排表与候选池；保存失败保留本地槽位、标题与团备注，状态保持「待保存」，可点击「保存排表」重试。请求序号与编辑版本共同阻止过期响应覆盖。
- 历史导入入口先完成当前保存；路由离开或切换赛程参数先尝试保存，失败可选择留下重试或明确放弃。登出、会话失效跳转登录不阻断；卸载时清理定时器并忽略旧回调。
- 边界：这不是多人协作乐观锁，也不保证关闭浏览器、强制刷新或登出时写入成功。未改变拖回候选池的保存触发规则（F05 不在本次范围）。

### F01/F04 人工回归清单

> 以下为待执行用例，不代表已通过；实际验证结果见 [progress.md](../../memory-bank/progress.md)。仅在隔离测试赛程使用合成数据。

1. **F01 特殊文本**：姓名、职业、阵营包含 `<b>测试</b>&"'`，检查散点、KDA、小队成员 KDA、热力图、堆叠、帕累托及评分 tooltip；必须显示原始文本，不能创建动态标签；静态粗体、换行和色点保持正常。原始姓名搜索、图例和统计值保持不变。
2. **F04 防抖切 Tab**：修改槽位及三类备注，在三秒内切出再切回；编辑不得丢失，保存成功后编辑器与总览一致。
3. **F04 在途新编辑**：模拟慢请求，保存 A 期间改为 B，再切 Tab；PUT 串行，最终落库 B，旧保存或旧 GET 均不得覆盖 B。
4. **F04 保存失败**：令 PUT 返回 500/超时，切回 Tab 后本地编辑仍在、保持待保存；恢复网络点击保存可成功，失败期间不显示已保存。
5. **F04 重载乱序**：交错两个 GET 或在 GET 在途时修改标题备注，只有最新且对应当前编辑版本的响应可以应用。
6. **F04 导入与离页**：待保存时打开历史导入，确认 PUT 完成后才允许导入；导入结果不被旧自动保存覆盖。路由离开/切换赛程先保存，失败选择留下保留编辑，选择放弃才离开；卸载后无定时保存或状态回调。
