## 1. 产品概述

### 1.1 产品定位
帮会管理系统是一款专为游戏帮会管理人员设计的一体化管理工具，涵盖成员管理、出勤考核、联赛排表、录屏审核和比赛数据分析等核心功能。

### 1.2 目标用户
- **开发者**（developer）：不绑定帮会，全局管理（创建帮会、派发账号、删除帮会）
- **管理员**（admin，帮会会长/副会长/官员）：进行帮会全面管理
- **帮众**（member）：查看录屏上传（联赛总览）、个人战绩、联赛日程；提交录屏、查看数据分析

### 1.3 设计理念
- **大气简约**：宣纸鎏金主色调，营造高端大气的视觉氛围
- **优雅一致**：统一的色彩、字体、间距规范，柔和的圆角和阴影
- **高效易用**：常用功能易于触达，操作反馈及时明确

## 3. 用户角色与权限

### 3.1 账号模型
系统配置**三级角色**：
- **开发者账号**（developer）：不绑定帮会，可创建帮会、派发账号、删除帮会，拥有全局管理权限
- **管理员账号**（admin）：绑定帮会，拥有帮会内全部功能权限
- **帮众账号**（member）：绑定帮会，共享账号，拥有有限功能权限

每个帮会配置**两个账号**（管理员 + 帮众），由开发者创建。

### 3.2 权限矩阵
| 功能模块 | 开发者 | 管理员 | 帮众 |
|---------|--------|--------|------|
| 创建帮会 | ✅ | ❌ | ❌ |
| 删除帮会 | ✅ | ❌ | ❌ |
| 账号管理（创建/删除/启禁用） | ✅（全局） | ✅（本帮会） | ❌ |
| 职业配置 | ✅ | ✅ | ❌ |
| 常驻库管理（成员CRUD） | - | ✅ | ❌ |
| 出勤库管理（导入/编辑/保存） | - | ✅ | ❌ |
| 出勤表查看 | - | ✅ | ❌ |
| 单人请假操作 | - | ✅ | ❌ |
| 排表编辑（拖拽编排） | - | ✅ | ❌ |
| 排表总览查看 | - | ✅ | ❌ |
| 录屏链接提交 | - | ✅ | ✅ |
| 录屏审核 | - | ✅ | ❌ |
| 游戏 ID 改名申请提交 | - | ❌ | ✅（共享账号代填，管理员核实身份） |
| 游戏 ID 改名审核 | - | ✅ | ❌ |
| 游戏 ID 改名记录查看 | - | ✅ | ✅（本帮会所选成员） |
| 数据分析查看 | - | ✅ | ✅ |
| 数据分析导入CSV | - | ✅ | ❌ |
| 联赛日程管理 | - | ✅ | ❌ |
| 个人战绩查看 | - | ✅ | ✅ |
| 成员详情战绩查看（基本信息+历史战绩） | - | ✅ | ❌ |

### 3.3 登录流程
- 开发者：账号密码登录，登录后进入系统配置（帮会管理 + 账号管理），并可使用系统日志（操作审计）
- 管理员：账号密码登录，登录后进入首页仪表盘，展示全部功能菜单
- 帮众：共享账号密码登录，登录后进入帮众首页（比赛焦点 + 录屏待办），仅展示有限功能菜单（首页 / 录屏上传 / 个人战绩 / 修改游戏 ID / 联赛日程）
- 登录限流：连续 5 次失败锁定 5 分钟，锁定期间禁用输入框并显示倒计时

## 4. 功能模块设计

### 4.1 常驻库模块（成员管理）

#### 功能列表
| 功能 | 描述 |
|------|------|
| 添加成员 | 填写姓名、主职业、副职业（可选）、状态、备注 |
| 编辑成员 | 修改成员信息 |
| 删除成员 | 删除单个成员 |
| 批量删除 | 勾选多个成员批量删除 |
| 搜索 | 按姓名关键词搜索 |
| 职业筛选 | 按主职业/副职业筛选 |
| 状态筛选 | 按正式/替补筛选 |
| Excel导入 | 批量导入成员，兼容旧模板与带来源行的新导出文件；写入归属只取当前账号帮会，重名跳过 |
| 成员导出 | Excel 各工作表含帮会名/ID；Excel/PNG 文件名含帮会名，仅作来源识别，不作为防伪凭证 |
| 出勤率统计 | 展示各成员出勤率，低于50%标红预警 |
| 改名审核 | 「改名审核」Tab：帮众提交的游戏 ID 修改申请待审列表，支持通过（同一事务同步常驻库名称并建立新旧 ID 关联）/驳回（必填原因）；状态筛选与关键词检索 |

#### 游戏 ID 改名申请（帮众提交 → 管理员审核）

- 帮众使用共享账号在「修改游戏 ID」页选择本帮会成员、填写新 ID 提交，状态为待审核；同一成员同时仅一条待审。
- 管理员在常驻库「改名审核」Tab 线下核实身份后通过或驳回；通过时在同一事务更新 `members.name`，历史出勤/排表/录屏/比赛数据原文不变。
- 管理员直接在常驻库编辑成员名称时，系统自动记录一条已确认的新旧 ID 关联（操作人快照 + 来源备注），个人战绩同样支持新旧合并。
- 帮众与管理员均可在个人战绩 / 成员详情中按已确认的新旧 ID 查询合并后的最近 10 场；发现名称归属冲突时停止自动合并，保留「仅查此 ID」。
- 完整状态机、API、事务与冲突边界见 `design-game-id-change.md`（表结构见 `database-design.md` §2.12）。

#### 成员状态
- `formal`：正式成员
- `substitute`：替补成员

#### 职业列表（11种）
铁衣、血河、沧澜、龙吟、潮光、玄机、碎梦、神相、九灵、鸿音、素问

#### 出勤率计算公式
```
出勤率 = 正常次数 / (正常次数 + 请假次数) × 100%
```
- 仅统计该成员被导入出勤表的场次
- 未被导入出勤表的赛程不计入统计
- 中途加入帮会的成员，之前的赛程不算缺勤

### 4.2 出勤库模块

#### 场次管理
- 创建赛程时自动创建关联的出勤场次
- 删除赛程时联动删除关联的出勤数据

#### 出勤管理流程
```
进入赛程详情 → 切换到出勤库
    ↓
一键导入正式成员
    ↓
系统提示当前人数与60人上限的缺口
    ↓
选择填补方式：导入替补成员 / 添加补人（补人）
    ↓
设置出勤状态（正常/请假，切换即时生效）
```

#### 出勤人数规则
- 出勤表正常状态人数上限为**60人**
- 可以不满 60 人（无独立保存步骤，状态切换即生效）
- 缺口提示：导入后若未达60人，提示缺少人数

#### 补人规则
- 补人仅在当前场次的出勤表中存在
- 补人**不录入常驻库**
- 下次比赛自动消失，需重新添加

#### 帮众操作权限
- 赛程详情页对帮众仅展示「录屏审核」「数据分析」Tab；出勤库与排表 Tab 仅管理员可见（与代码一致）
- 出勤状态切换为管理员操作（接口与 UI 均限管理员）

### 4.3 联赛排表模块

#### 页面结构
排表页面包含**三个核心模块**，排表总览在视觉布局和交互逻辑上需与候选池、具体排表明确区分：

```
┌─────────────────────────────────────────────────┐
│                  排表页面                         │
├─────────────────────────────────────────────────┤
│  ┌─────────────┐  ┌─────────────────────────┐   │
│  │  候选池模块   │  │     具体排表模块         │   │
│  │             │  │                         │   │
│  │ 60人列表    │  │  10支队伍 × 6人/队      │   │
│  │ 可拖拽      │  │                         │   │
│  │             │  │                         │   │
│  └─────────────┘  └─────────────────────────┘   │
├─────────────────────────────────────────────────┤
│            排表总览模块（独立区域）                │
│  ┌─────────────────────────────────────────┐    │
│  │  成员列表 + 备注 + 位置信息              │    │
│  │  （供帮众查看自己在哪个位置）             │    │
│  └─────────────────────────────────────────┘    │
└─────────────────────────────────────────────────┘
```

#### 候选池
- 来源：出勤库中状态为**正常**的成员（含正式、替补、补人）
- 最多60人
- 支持拖拽到排表槽位

#### 排表结构（固定不可修改）

| 分类 | 队伍数量 | 每队人数 | 小计 |
|------|---------|---------|------|
| 进攻1 | 3队 | 6人 | 18人 |
| 进攻2 | 3队 | 6人 | 18人 |
| 防守1 | 2队 | 6人 | 12人 |
| 防守2 | 2队 | 6人 | 12人 |
| **合计** | **10队** | - | **60人** |

#### 排表交互
- 拖拽：从候选池拖拽成员到槽位
- 交换：两个槽位之间成员位置互换
- 角色标签：为槽位添加备注

#### 排表总览
- 展示内容：成员姓名、备注、所在位置
- 用途：发给帮众查看，让帮众知道自己在哪个位置
- 视觉设计：需与候选池和具体排表模块明显区分

#### 导出功能
- 导出排表为PNG图片

### 4.4 录屏审核模块

#### 使用场景
比赛后，帮众提交回放视频链接供管理员审查。

#### 数据来源
- 录屏列表展示**候选池中全部60人**（含正式、替补、补人）
- 根据赛程局数（1-3局），每人可提交对应数量的录屏URL

#### 功能列表
| 功能 | 描述 |
|------|------|
| 多局链接展示 | 同屏展示所有局数的链接输入框（不支持局数切换） |
| URL提交 | 帮众按局数提交录屏URL |
| URL校验 | 验证URL格式有效性（支持B站、YouTube等） |
| 审核通过 | 管理员审核通过，显示勾选标记 |
| 审核驳回 | 管理员驳回，要求重新提交 |
| 批量审核 | 批量审核通过多个帮众的录屏 |
| 审核筛选 | 按状态筛选（待审核/已通过/已驳回） |
| 全局进度 | 展示各局审核完成进度（如：第1局 45/60 已审核） |

#### 审核状态
- `pending`：待审核
- `approved`：已通过
- `rejected`：已驳回

#### 操作角色
- **帮众**：提交/修改自己的录屏链接
- **管理员**：审核通过/驳回，查看全局进度

### 4.5 数据分析模块

#### 数据导入
- 支持导入CSV格式的比赛数据（游戏内导出）
- CSV格式样例见 `.agent/docs/20260630_213158_横戈_仗剑.csv`
- 文件大小限制：5MB
- 数据与**赛程绑定**，按局导入（一局一表，重新导入覆盖该局数据）

#### 数据展示
| 展示项 | 描述 |
|--------|------|
| 多阵营对比 | 不同阵营的比赛数据对比（总览/阵营对比 Tab，含差值/波动值） |
| 击杀榜 | 各成员击杀数排行 |
| 伤害榜 | 各成员伤害输出排行 |
| 治疗榜 | 各成员治疗量排行 |
| 职业分析 | 按职业维度分析数据分布（职业分析 + 职业深度 17 项指标） |
| 衍生指标 | 16 项衍生指标（效率/生存/占比/技能四类），见数据列表 Tab |
| 小队分析 | 按排表小队维度分析我方成员（含小队对比与成员明细） |

#### 报告导出
- 单场图文战报（PNG）：数据分析页一键生成整场战报（仅统计我方阵营：对局信息/我方总览/MVP 与数据之王/六榜 TOP3（击杀、对玩家伤害、治疗、对建筑伤害、重伤、总分）/逐局战况/小队战况），供群内分享
- HTML 分析报告导出已移除（2026-08 数据分析模块重实施时删除，相关描述与代码同步清理）

#### 操作角色
- **管理员**：导入CSV、查看分析、调整小队分配
- **帮众**：查看分析数据

### 4.5.1 分析调整模块

#### 功能说明
小队分析 Tab 内，管理员可手动将"未排表成员"分配到指定队伍，用于分析视图中更精确的小队数据对比。该调整**仅作用于小队分析视图**，不改变正式排表数据。

#### 功能列表
| 功能 | 描述 |
|------|------|
| 读取调整 | 读取当前赛程的分析调整数据（帮众/管理员均可查看） |
| 保存调整 | 管理员保存「未排表成员 → 目标队伍」的分配方案 |
| 调整重置 | 覆盖式保存，新方案替换旧方案 |

#### 操作角色
- **管理员**：保存分析调整
- **帮众**：查看分析调整结果

### 4.6 联赛日程模块

#### 日程管理

```
创建赛程（对手/时间/地点）

  - 排表（关联该赛程）
  - 录屏上传表（根据局数预留链接位置）
```

#### 数据关联关系
```
赛程 (1) ──→ (1) 出勤库
赛程 (1) ──→ (1) 排表
赛程 (1) ──→ (1) 录屏上传表
赛程 (1) ──→ (1) 数据分析
```

### 4.8 个人战绩模块（帮众）

#### 功能列表
| 功能 | 描述 |
|------|------|
| 玩家搜索 | 输入游戏 ID 模糊搜索，自动补全候选（基于本帮会比赛数据 + 已确认改名关系的新旧 ID） |

#### 操作角色
- **帮众**：查询游戏 ID 的历史战绩（共享账号，不绑定个人身份）
- **管理员**：侧边栏新增「个人战绩」菜单，可自由按 ID 搜索任意成员

> 合并/精确查询的判定、冲突边界与响应结构见 `design-game-id-change.md`。

### 4.8.1 成员详情战绩页（管理员）

#### 功能说明
从常驻库点击成员进入独立详情页（`/members/:id`），整合成员基本信息与历史战绩，用于成员考核、排表参考与沟通反馈。

#### 功能列表
| 功能 | 描述 |
|------|------|
| 成员信息 | ID、主/副职业、状态、备注、出勤率（低于 50% 预警） |
| 历史战绩 | 复用个人战绩组件：概览、趋势图、每局排名、单局明细（最近 10 场）；默认合并已确认的新旧 ID，冲突时提示并跳转个人战绩精确查询 |
| 入口 | 常驻库列表点击成员 ID（桌面端）/ 成员名（移动端） |

#### 操作角色
- **管理员**：查看任意成员
- **帮众**：不可访问（帮众仍使用「个人战绩」查询）

### 4.9 系统日志模块（开发者）

#### 功能列表
| 功能 | 描述 |
|------|------|
| 审计日志 | 所有写操作（POST/PUT/DELETE/PATCH）与异常自动记录，支持按账号/模块/级别/时间筛选与分页 |
| 概览统计 | 日志总量与级别分布（info / warning / error） |
| 保留期清理 | 按保留天数清理历史日志（默认 90 天；服务启动清理一次，此后每日一次） |

#### 操作角色
- **开发者**：查看与清理（管理员、帮众不可见）
