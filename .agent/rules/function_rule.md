# 模块开发文档规则

## 文档要求

每个功能模块都必须有独立的开发文档，文档必须包含以下信息：

### 文档结构

```
模块名称/
├── docs/
│   ├── README.md        # 模块开发文档（必需）
│   └── 其他文档.md      # 可选
└── ...
```

### 必需内容

#### 1. 需求说明
- **功能概述**：模块的主要功能描述
- **业务目标**：解决什么问题，达到什么效果
- **用户场景**：主要使用场景

#### 2. 开发计划
- **功能清单**：需要实现的所有功能点
- **优先级**：功能优先级排序（P0/P1/P2）
- **依赖关系**：与其他模块的依赖关系

#### 3. 进度跟踪
- **当前状态**：未开始/进行中/已完成
- **完成进度**：百分比或具体完成项
- **下一步计划**：接下来要做什么
- **更新日期**：最后更新时间

### 文档模板

```markdown
# 模块名称 开发文档

## 需求说明

### 功能概述
[简要描述模块功能]

### 业务目标
[描述要解决的问题]

### 用户场景
[描述主要使用场景]

## 开发计划

### 功能清单
- [ ] 功能1（P0）
- [ ] 功能2（P1）
- [ ] 功能3（P2）

### 依赖关系
- 依赖模块A：xxx
- 依赖模块B：xxx

## 进度跟踪

### 当前状态
**状态**：进行中
**完成进度**：60%

### 已完成
- ✅ 功能1
- ✅ 功能2

### 进行中
- 🔄 功能3

### 待开始
- ⏳ 功能4

### 下一步计划
[描述下一步要做的事情]

### 更新记录
| 日期 | 更新内容 |
|------|----------|
| 2024-01-01 | 初始化文档 |
| 2024-01-15 | 完成功能1开发 |
```

## 更新规则

1. **创建时机**：开始开发新模块时必须创建
2. **更新频率**：每完成一个功能点必须更新
3. **审核要求**：重要模块需团队审核
4. **归档要求**：模块完成后文档保留，状态标记为"已完成"

## 违规处理

未按要求创建或更新文档的模块，不允许合并到主分支。
